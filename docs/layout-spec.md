# 布局设计依据（layout-spec）

> 本文件回答一个问题：**现在的布局为什么长这样**。
> 改尺寸、加断点、动 `#table` / `#river` 的 Grid 之前，请先读一遍「决策记录」。

## 0. 先说结论

**桌面端和手机端现在是同一套 Grid**，只有 3 个断点在改尺寸变量：

```
#table  五行（单列）  north / nback / river / acts / hand
#river  三列 × 三行   side-w | 1fr | side-w
```

所以严格说已经不存在"桌面版布局"和"手机版布局"两套东西——
**只有一套布局在覆盖 320px ~ 1920px**。本文件描述的就是这一套。

（重构前确实是两套思路：桌面靠 `.area` 绝对定位把四家按东南西北摆四周，
窄屏再 `display:none` 掉左右两家。那条路的代价就是你截图里看到的"南北两家不见了"。）

## 1. 参考来源

手机端重构时查证过 3 个来源。**都是间接参考**——读的是公开文档/教程里的布局描述与结构，
没有逐像素抄任何一款产品。

| 来源 | 是什么 | 借了什么 | 没借什么 / 为什么 |
|---|---|---|---|
| [killer_mortal_gui](https://github.com/killerducky/killer_mortal_gui)（[布局文档](https://deepwiki.com/killerducky/killer_mortal_gui/4.1-css-grid-layout-system)） | 日本麻将 AI 的**桌面复盘器**，CSS Grid + 模板区域 | ① 用 `grid-template-areas` 的**字符画**表达麻将桌（它的 5×5 `grid-main`：`ah-p0..p3` 手牌 + `ad-p0..ad-p3` 弃牌 + `a-info` 信息）；② 用 `--zoom` 一个主变量派生所有尺寸 | **没借它的"四家各自独立弃牌区"**——它是给天凤牌谱复盘用的，桌面 655×735px 空间够，四家弃牌各占一边很自然；手机上这么摆必然有一家被挤没 |
| [Godot 2.5D 麻将教程 · 第 8 章 UI 布局](https://www.evocosmos.com/a-doc-godot-dev-docs/2-5d-game-guide/2-practice/mahjong/8-polish-release.html) | 游戏开发教程，给出了一张完整的麻将 UI 分区 ASCII 图 | **"弃牌区域 = 桌面中央，显示所有打出的牌"**、对手只显示牌背、自己手牌在底部中央、操作按钮在手牌附近、剩余牌数/回合指示放角落 | 它是 3D 场景 + Godot 控件，前端实现完全不同；只取其**信息分区逻辑** |
| 方向锁可用性调研 | iOS Safari / 微信内置浏览器 | 确认 `screen.orientation.lock()` **在 iOS Safari 不支持、微信浏览器被拦**，H5 无法强制横屏 | —— 这条直接决定了 D2 |

### ⚠ 一处明确的"自行发挥"

**中央共享牌河（四家弃牌全部落进同一个 `#river`）不是任何参考源的现成做法**：

- killer_mortal_gui 是四家各占一边（`ad-p0..ad-p3`）
- Godot 教程只说"弃牌在桌面中央"，没说四家怎么组织

把它做成"四家共享一条中央牌河 + 上下家在左右两列"，是**移动端的空间妥协**：
竖屏真正缺的是高度，四家各占一边会在四个角落各留一堆死空间；
合成一条中央带，富余高度才能集中起来给弃牌和中央信息用。
这个取舍当时也征询过你（选项：中央共享牌河 / 四角分区），你选了前者。

## 2. 从参考源里提取的共同模式

三个来源交叉后，成熟麻将 UI 的稳定共识是这 4 条：

1. **自己的手牌在屏幕底部、正面朝上、一行展开**（唯一需要看清全部细节的区域）
2. **对手只展示牌背 + 元信息**（风位/分数/花数），不展示具体牌
3. **打出的牌集中在桌面中央**，是公共信息区
4. **操作按钮（碰/杠/吃/和）紧贴手牌上方**，回合/余牌等状态放角落或中央

本项目的对应关系：1→`#area-south .hand-area`；2→`backs-* / seat-head`；
3→`#river`；4→`#action-bar` + `#topbar` + `#center-info`。

## 3. 决策记录

每条都写清"为什么这么做"和"不这么做会怎样"。

### D1 · 一套 DOM，不用两套布局

**决定**：横竖屏共用一套 DOM 和一个 `#table` Grid，只靠 Grid 行高与尺寸变量切换。
**理由**：重构前的教训——`@media (max-width:620px){ #area-east,#area-west{display:none} }`
直接把南北两家隐藏了（座位映射是 p1→右、p3→左）。**任何"窄屏就藏东西"的规则都会丢信息**。
**代价**：横屏时侧列只能露出最近 8~10 张弃牌（见 D5）。

### D2 · 竖屏必须能玩

**决定**：不为横屏做特殊优化，优先保证竖屏可玩。
**理由**：`screen.orientation.lock()` 在 iOS Safari 不支持、微信浏览器被拦，H5 无法强制用户横屏。
指望"提示用户转横屏"等于把一半用户挡在门外。

### D3 · 手牌尺寸用 `min()` 锁死，永不出屏

```css
--tile-ar: 1.381;                                  /* 58/42，牌面真实比例 */
--hand-w: min(var(--tile-w), calc((100vw - 51px) / 14));
--hand-h: calc(var(--hand-w) * var(--tile-ar));
```

**51px** = 左右各 6px 内边距 + 13 个 3px 间隙。
**为什么**：14 张是满手牌，必须一行装下。旧版让 flex 自己压，结果宽高比从 0.71 掉到 0.52，牌面被挤糊。
高度由宽度乘 `--tile-ar` 推出，**绝不单独写死高度**。

### D4 · 上下家那一列给固定宽 `--side-w`

**理由**：中间那条越宽 → 对家/自己两条弃牌带折行越少 → **越省高度**。
横屏最缺的正是高度，所以横屏把 `--side-w` 从 104px 收到 96px。
（这条是反直觉的：给侧边"固定宽度"是为了给中间"省高度"。）

### D5 · 横屏（h ≤ 600）把中央格压到 0

```css
#river{ grid-template-rows:minmax(0,1fr) 0px minmax(0,1fr); }
#center-info{ display:none; }
```

**理由**：横屏牌河总高只有 ~147px，中央信息区（需要 115px）会吃掉全部。
**代价**：横屏看不到"最后打出"，且侧列只能露出最近 8~10 张弃牌——物理极限，
20 张旋转 90° 的牌叠起来要 480px，横屏根本没有 480px。

### D6 · 后期自动缩档 `.tight`

每家弃牌 > 22 张时给 `#river` 挂 `.tight`（`--mini-scale: .78`，且只在 `min-height:601px` 生效）。
**理由**：弃牌带多折两行会把中央那张"最后打出"挤没——**宁可牌小一点，不能丢信息**。
**为什么限定 min-height**：横屏本来就放得下，缩档反而让牌变大、更挤。

### D7 · 中央显示"最后打出"（竖屏专用）

竖屏弃牌放大到 30px 也认不清具体是哪张，所以在中央放大显示**最后一张弃牌 + 是谁打的**。
顺带把竖屏中央原本 30%~60% 的死绿用起来了。
新增字段 `game.lastDiscardBy`（`lastDiscard` 原本只记牌、不记人）。

### D8 · 长按手牌弹放大条

**理由**：竖屏手牌只有 24px 宽。但**单击 = 出牌**，不能直接做成"点击放大"。
所以用 `pointerdown/move/up` 长按触发，并在**捕获阶段**吞掉随后的 `click`
（否则放大完手指一松就把牌打出去了）。

### D9 · 横屏侧列弃牌放不下 → 点侧列弹浮层

**问题**：横屏牌河总高 ~147px，而 20 张旋转 90° 的牌叠起来要 480px——
侧列物理上只能露出最近 8~10 张，**调尺寸无解**（除非把弃牌缩到不可辨认）。

**决定**：整个侧列（`.rz-w` / `.rz-e`）可点，弹出该家浮层：
副露 + 全部弃牌按**正常方向、正常尺寸**（`--tile-w`，不受 `#river .tile.mini` 缩放影响）重排。
侧列有弃牌时在**座位信息条**里亮金色 chip「▸N」（N=弃牌总数）——
没有它用户不知道底下压着牌、这里能点。浮层开着时游戏继续推进，`renderAll` 会实时刷新其内容。

**角标演化（v2→v3）**：最初做成绝对定位钉在侧列右下角的「▸ 看全部」角标，
真机截图发现它正好压住侧列**最新的几张牌**——弃牌是 `flex-end` 靠底排，
右下角是最不该挡的位置。v2 改成信息条里的金色文字 chip「▸21」，用户反馈认不出是入口；
v3 定稿为信息条里的**金色药丸「▸看全部」**（title 里带张数），位置在列顶、不挡牌、文案自解释。

**整行裁切（v3 关键修复）**：`#table` 里 river 是 `minmax(0,1fr)`，其余行是 auto——
视口一矮，river 内部被压扁，flex 等比收缩把弃牌**拦腰切成半张**、副露压扁、牌背挤成细条
（用户 400×948 实测截图）。修复分三层：
① 侧列固定内容（信息条/副露/牌背）`flex-shrink:0`，空间不够只准裁弃牌；
② 四个弃牌区从 flex 改成 **grid 固定行高**：`grid-auto-rows` 精确等于一张牌的高
（侧列是旋转占位：宽=牌高、高=牌宽；上下带是正立牌：反之），
**`align-content` 必须显式写 `end`**——基类的 `flex-end` 对 grid 是非法值、会退化成 `start`，
那样行块贴顶、裁掉的是最新的牌，刚好反了；
③ 网格只保证行高固定，**容器高不整除行高时顶端仍会剩半行残牌**，
而 CSS 无法表达「取整行数」——所以由 `syncOverflowMarks()` 量出行高、把高度写成整行数
（先删 `.snap`/清空 height 还原 `flex:1` 才量得到真实可用高度）。
⚠ 判断"装不下"**不能用 `scrollHeight`**：`align-content:end` 把溢出部分推到了容器**上方**，
负方向溢出不计入 `scrollHeight`，会误判成"装得下"。要按 `gridTemplateColumns` 的列数
自己算自然高度（`ceil(n/cols)*(rowH+gap)-gap`）。
`renderAll` 末尾调一次 + `window.resize` 上再挂一次（转屏/拖窗口不触发 renderAll）。
`#center-info` 在高度 <110px 时收起「最后打出」（该块实测要 ~103px），
否则它会从中央格顶部漏出半张牌残影。

**两个实现细节**：
- 遮罩关闭判据用 `e.target === e.currentTarget`，**不要比对 `e.target.id`**——
  自测的 DOM mock 元素没有 `id` 属性，比对 id 会让"点遮罩关闭"在测试里永远失败。
- 浮层标题沿用全项目命名约定 `WINDS[p]+'·AI'`（玩家编号 → 名字，与 toast 一致）；
  本局风位另用 `WINDS[seatWind(p)]` 表示，两者语义不同：前者是固定座位名、后者随庄家变。

## 6. 三道验证防线

改完任何尺寸都必须跑：

```bash
node scripts/sim_layout.js     # ① 几何试算：12 个视口，纯计算不依赖浏览器
node test/selftest.js          # ② 逻辑自测：含布局相关契约（PASS=62）
bash scripts/shoot.sh          # ③ 真机尺寸截图：本机 Chrome 无头 + 精确 iframe
```

外加 `layout-preview.html`（多设备 iframe 同屏预览，`#auto&fill=N` 可灌满弃牌看最挤的样子）。

> ⚠ 截图工装的坑：无头 Chrome 的 `--window-size` **不等于视口**（请求 390 实得 504），
> 必须靠页面内精确尺寸的 iframe 来定尺，否则截图右侧被裁、会误判成"某一家的牌不见了"。
